# 任务实现阶段

## 执行循环

对 `.aidlc/tasks.md` 中第一个未勾选任务重复以下步骤：

1. 读取任务全文及所有需求、设计、`[Reference]` 引用。
2. 检查 `Depends on` 已完成；若未完成，先修正任务顺序或前置问题。
3. 阅读任务影响范围内的现有代码、测试、配置和版本控制差异。
4. 形成最小实现方案，确认接口与相邻模块一致。
5. 编写代码和必要测试，保持现有工程风格。
6. 运行任务列出的验证命令，并检查实际输出。
7. 对失败定位根因并修复，直到验收标准满足。
8. 在任务下记录实现摘要、验证命令与结果，再勾选复选框。
9. 继续下一个任务。

## 完成判定

只有同时满足以下条件才勾选任务：

- 任务范围内的交付物已经存在且可运行。
- 所有验收标准均有验证证据。
- 新增或修改行为有与风险相匹配的测试。
- 相关构建、类型检查、静态检查和测试通过，或不可运行原因已记录并得到用户接受。
- 没有通过硬编码假数据、吞掉异常、跳过权限或禁用测试来伪造完成。
- 接口、数据迁移、配置示例和必要运行文档保持一致。

## 现有代码与变更

- `src/` 已存在时，先识别模块边界、入口、依赖管理、测试方式和当前未提交改动。
- 不回退、不覆盖用户改动。遇到同文件改动时理解并兼容。
- 优先复用现有框架、组件、数据访问和错误处理模式。
- 引入依赖前确认必要性、许可证/维护状态和锁文件更新。
- 对外部 API、数据库迁移和破坏性操作先使用非生产环境；需要凭证或批准时明确阻塞点。

## 任务记录示例

```markdown
### T-004 任务状态流转
- [x] 状态：已完成
...
- 实现记录：新增受权限约束的状态转换和审计事件。
- 验证记录：`npm test -- task-status`，18 项通过；`npm run typecheck` 通过。
```

如果部分实现但未达到验收条件，保持 `[ ]`，记录“进行中”、已完成部分和下一步，不把进度误报为完成。
