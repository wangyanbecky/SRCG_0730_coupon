## 增量需求 2（2026-07-30）

### 输入
预约发布活动在 operator 中应显示待发布；普通用户应提前看到活动和领取起始时间，提前点击领取可确认预约，预约后显示收藏图标。

### 执行计划
- [x] 分析现有预约发布、用户展示和领券流程
- [x] 确认收藏能力与数据缺口
- [x] 编写 FR-004 至 FR-007
- [x] 编写 NFR-005 至 NFR-006
- [x] 编写 US-003 至 US-004 及场景
- [x] 更新需求清单与追踪入口

### 决策与默认值
- “预约”定义为当前用户对未来活动的持久化收藏/关注，不自动领取、不扣库存、不加积分、暂不发送通知。
- 收藏状态必须跨刷新和重新登录保留，因此使用数据库关系，不使用浏览器本地状态。
- 待发布状态由服务端当前时间动态推导，不批量改写旧活动状态。
- 用户明确要求直接实施，本增量需求视为已认可，无待回答问题。
