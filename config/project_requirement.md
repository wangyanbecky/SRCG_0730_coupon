# 优惠券发放与核销系统 — 需求规格文档

## 一、项目简介

构建一个优惠券发放与核销系统。运营创建优惠券活动，用户领取和使用优惠券，管理员查看统计数据。系统引入 AI 能力提升体验与安全性。采用本地单机部署，SQLite 存储，通过 API Token 调用 Amazon Bedrock 提供 AI 推理。

## 二、用户角色

| 角色 | 职责 |
|---|---|
| 运营人员 | 创建/管理优惠券活动，审核风控标记，发送广播通知 |
| 普通用户 | 浏览、领取、查看优惠券，管理个人资料 |
| 核销人员 | 通过手机号或券码核销优惠券 |
| 管理员 | 查看统计数据，监控异常 |

## 三、功能需求

### 3.1 核心业务

#### 活动管理（运营人员）
- 创建/编辑优惠券活动：名称、面额、库存、有效期、每用户限领数、用途描述
- 优惠券领取情况洞察：领取占比、按时间排序
- 活动预告与广播：可选择目标用户或全员推送
- 预约定时发布优惠券

#### 用户领券（普通用户）
- 库存原子扣减，不可超发
- 每用户限领校验
- 用户注册：用户名+密码，手机号可选，个人信息（年龄、性别、爱好、职业）可跳过
- 领券界面：系统广播、AI 推荐排序、临期优惠券提醒、我的优惠券列表
- 积分体系：领券 +10、核销 +5、过期未核销 -5、7天未登录 -3

#### 核销（核销人员）
- 幂等核销：重复请求返回一致结果
- 过期券不可核销
- 通过用户手机号查找候选优惠券核销
- 通过券码直接核销（券码核销同样幂等）
- 核销界面预留二维码扫描控件接口

#### 统计面板（管理员）
- 展示领取率、核销率、剩余库存
- 可按参数排序显示优惠券情况

### 3.2 AI 增强功能

#### 智能推券
- 根据用户画像（年龄、性别、爱好、职业）和优惠券属性，调用 Bedrock AI 生成个性化推荐列表 + 推荐理由
- AI 不可用时降级为规则引擎：按过期紧急度 > 面额 > 库存稀缺 > 爱好匹配

#### 异常检测（风控）
- 领券时评估用户行为风险，返回评分与决策：`allow`（放行）/ `block`（拦截）/ `review`（人工审核）
- AI 不可用时降级为规则引擎：统计时间窗口内操作频率
- 风控参数可配置：时间窗口（秒）、窗口内最大操作数

### 3.3 AI 服务架构

- **API Key 模式（推荐）**：通过 `AWS_BEARER_TOKEN_BEDROCK` 环境变量配置 Bearer Token，HTTP POST 调用 Bedrock Converse API
- **SDK 模式**：通过 boto3 使用 AWS 凭证调用
- **降级模式**：AI 不可用时自动切换规则引擎，页面状态指示灯显示当前模式
- 模型：`deepseek.v3.2`（可通过 `BEDROCK_MODEL_ID` 配置）
- 区域：`us-east-1`（可通过 `AWS_REGION` 配置）

## 四、功能边界与验收标准

| # | 验收项 | 预期结果 |
|---|---|---|
| 1 | 库存为 N，N+1 个并发领取 | 只有 N 个成功 |
| 2 | 同一用户重复领取 | 返回"已领取"或"已达上限" |
| 3 | 过期券核销 | 返回"券已过期" |
| 4 | 重复核销 | 幂等，多次结果相同 |
| 5 | AI 推荐 | 返回非空推荐列表 + 理由文本 |
| 6 | 短时间高频领取 | 触发风控拦截 |
| 7 | 用户注册登录 | 支持（含 Mock 用户） |
| 8 | 金额结算/支付 | 无需对接 |

## 五、演示流程参考

1. 创建库存为 1 的活动
2. 用户 A 领取 → 成功（含 AI 推荐理由）
3. 用户 B 领取同一券 → 失败（库存不足）
4. 用户 A 核销 → 成功
5. 用户 A 再次核销 → 返回"已核销"（幂等）
6. 用户 C 10 秒内 5 次领取 → 风控拦截

## 六、技术栈

| 层面 | 技术 |
|---|---|
| 框架 | Flask 3.0 + Jinja2 |
| 数据库 | SQLite + Flask-SQLAlchemy |
| 认证 | Flask-Login（Session） |
| AI | Amazon Bedrock Converse API（DeepSeek V3.2） |
| AI SDK | boto3（SDK 模式）/ requests（API Key 模式） |
| 前端 | 原生 HTML/CSS/JS（无框架），CSS Grid 布局 |
| 部署 | 本地单机 `python run.py` |
